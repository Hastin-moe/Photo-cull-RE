# 照片工具 photo-cull

[简体中文](README.md) · **繁體中文** · [English](README.en.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

工具包含兩個程式，放在**同一個視窗**裡，右上角一點就切換（⌘1／⌘2），兩邊的進度和狀態都保留。macOS 上可以打包成獨立的 **「照片工具.app」**，雙擊就用，不需要終端（見下文「Mac 應用」）：

- **照片篩選**（雙擊 `启动照片工具.command`）：先在本地做技術篩選，包括對焦、模糊、曝光、人臉與閉眼檢測，以及連拍和同場景重拍分組，每組連拍按「精彩幀權重」挑出一張。挑出來的照片可以再交給 **Claude、ChatGPT、Grok、Gemini、DeepSeek**，或任何 OpenAI 相容的視覺模型（通義千問、Kimi、豆包、OpenRouter、本地 Ollama 等）做審美細評。評分是 **10 分制**：本地技術分最高 6 分，6 分以上只由 AI 給出。分數折算成**星級和色標**寫進 XMP，Lightroom Classic 和 Capture One 都能讀到，同時生成一份可以直接操作的網頁報告。
- **外掛**：單獨安裝的程式可以作為外掛接進一體視窗（每個外掛一個頁籤，按需啟動，各自更新）。目前有 **膠片沖印**（[photo-cull-film](https://github.com/Hastin-moe/photo-cull-film)，GPLv3）：用 [spektrafilm](https://github.com/andreavolpato/spektrafilm) 做光譜級的膠片模擬（負片、相紙、顆粒、光暈）。裝了膠片沖印後工作流是 **篩圖 → 膠片沖印 → 編輯**（頁籤和 ⌘1／⌘2／⌘3 按這個順序；外掛說明的 `order` 小於 50 就排在編輯前面）。外掛協議見 `photo_cull/server/plugins.py`。
- **照片編輯**（基礎版）：對整張畫面做調整，包括曲線、直方圖和波形圖監看；可以套用 `.cube` LUT 和 Lightroom／Photoshop 的 XMP 預設，最後匯出 JPEG 或 16 位 TIFF。支援徠卡 DNG、松下 DNG、索尼全部 ARW、富士 RAF。

**介面語言**：繁體中文、繁體中文、English、日本語、한국어（Mac 系統的這五種語言；繁體 11-21 加），在兩個程式右上角切換（兩個程式同步）。報告頁、執行日誌、執行報告、AI 評語，以及整理輸出、快速篩片、報告資料夾裡**所有資料夾和檔案的名字**都跟隨所選語言；第一次開啟時按系統／瀏覽器語言自動選擇（zh-Hant、zh-TW、zh-HK 算繁體）。

**RAW＋JPEG 自動配對**：同一資料夾裡同名的 RAW（DNG、ARW、RAF 等）和 JPEG 會被當成一張照片來評分。打分時兩個檔案同步標記，刪除時兩個檔案一起刪除。

**安全保證**
- 畫面資料永遠不會被修改。
  - RAW 的星級寫在邊車檔案 `同名.xmp` 裡，原檔案不動。
  - JPEG 的星級寫進檔案內嵌的 XMP 段，只改後設資料。寫完會逐位元組核對影像資料（包括相機附帶的多圖預覽）有沒有變化，任何異常都會放棄寫入。
- 已有的 XMP 只改星級和色標，調色、關鍵詞等內容原樣保留。第一次改別的軟體寫過的邊車 XMP 之前，會先備份一份 `.xmp.cull-bak`。
- “刪除”只會把檔案移到**廢紙簍**，可以恢復，不會直接抹掉。
- 整理輸出預設是**複製**，原資料夾保持不變；只有你選了「移動」才會搬動原檔案。

## 安裝（只需一次）

只支援 macOS（2026-11-17 起暫停 Windows 版）。需要先裝好 Python 3.9 以上（[python.org](https://www.python.org/downloads/)）。

雙擊 **`启动照片工具.command`**：第一次會自動建執行環境、聯網安裝依賴（約 1–5 分鐘），之後每次雙擊直接開啟。啟動後先出現 Let's start，選好照片資料夾後，篩選、編輯（裝了膠片沖印時還有它）都在同一個視窗裡。

### 修復環境

環境壞了時，雙擊 **`tools/修复环境.command`**。它會：

1. 在工具資料夾裡建獨立的執行環境 `.venv`，不影響電腦上的其他 Python；
2. 安裝 `requirements.txt` 裡的依賴。預設先試 PyPI 官方源，4 秒內連不上就自動改用清華映象；
3. 逐個檢查元件能不能真正用（numpy、Pillow、OpenCV、rawpy／LibRaw、ExifRead、cryptography 必需；HEIC、廢紙簍、AI 細評可選），再檢查內建 LUT 和設定資料夾，最後列出結果。

`requirements.txt` 有變化時，啟動檔案會自動補裝。在終端裡可以帶引數：

| 引數 | 作用 |
|---|---|
| `--check` | 只檢查，不安裝 |
| `--recreate` | 刪掉舊環境重新裝（環境壞了、換了 Python 版本時用） |
| `--mirror tuna`／`aliyun`／`ustc`／`pypi`／網址 | 指定 pip 源（預設 `auto`） |
| `--wheels 文件夹` | 從本地資料夾離線安裝，不聯網 |
| `--download 文件夹 --target mac-arm／mac-intel` | 在能聯網的電腦上先下載好安裝包（配合 `--target-python`），拷過去後用 `--wheels` 離線安裝 |

想手動安裝的話，開啟「終端」：

```bash
cd ~/Desktop/照片筛选工具
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

## Mac 應用（推薦）

雙擊工具資料夾裡的 **`打包Mac应用.command`**，會生成 `dist/mac/照片工具.app`：
- 自帶 Python 和全部依賴，拷到別的 Mac（Apple 晶片，macOS 11 以上）也能直接用；
- 原生視窗，不開終端、不開瀏覽器；照片篩選和照片編輯在同一個視窗裡切換；
- 第一次打包要聯網下載打包工具，約 3–8 分鐘；用單獨的 `.venv-build` 環境，不影響平時的 `.venv`；
- 打好後會自動自檢（依賴、內建 LUT、兩個服務），並生成可以發給別人的 `dist/照片工具-<版本>-macOS-app.zip`。

把 `照片工具.app` 拖進「應用程式」，以後從啟動台或程式塢開啟。關閉視窗即退出。出問題時的記錄在 `~/.photo-cull/logs/app.log`，打包記錄在 `dist/mac/build.log`。
從網上下載別人打包的 `.app` 時，第一次請右鍵 →「開啟」（應用沒有經過蘋果公證）。

**開發版和發布包**：在這個資料夾（開發版）裡打包的應用**不需要啟用碼**，作者自己用。要發給別人時，雙擊 `tools/导出发布版.command`：在暫存資料夾裡精簡匯出、寫進共用啟用碼的雜湊（啟用碼本身不寫進任何檔案）、打包，成品 zip、安裝與啟用說明、發布紀錄放進旁邊的 `photo-cull-main-release`，並複製一份到 `Grey-test/<版本>/`。這樣打出來的應用第一次開啟要輸入啟用碼。`Grey-test` 是各測試版的總資料夾，只放成品包和灰度測試文件；灰度版的精簡原始碼用 `tools/导出灰度版.command` 匯出到 `build/grey-export`（只在本機）；私有倉庫 Photo-cull-RE 只放說明和開發日誌。程式碼只在開發版裡改。

**啟用碼**：只有釋出版檢查。啟用碼由作者用 `tools/激活码生成器.command` 發放：第一次執行會生成一把金鑰，私鑰只存在作者電腦的 `~/.photo-cull-keys/` 裡（務必另外備份），公鑰寫進 `photo_cull/activation_key.py` 隨應用釋出。啟用碼可以設有效期，也可以繫結對方電腦的「本機編號」（啟用頁面上能看到）。還沒生成金鑰時，打包指令碼會拒絕打包。

## 圖形介面

雙擊 **`启动照片工具.command`**，瀏覽器會開啟「照片工具」視窗。右上角的「照片篩選｜照片編輯」直接切換；已經開著時再雙擊，只會開啟現有的視窗，不會起第二份。

照片篩選的用法：

1. 點「選擇…」，挑一個照片資料夾。如果這個資料夾之前篩選過，可以點「載入這個資料夾上次的結果」，直接繼續複核。
2. 選「僅本地篩選」，或者「本地＋AI 細評」。選細評時還要：
   - 選服務商：Claude、ChatGPT、Grok、Gemini、DeepSeek 或「自訂」；
   - 從下拉選單選模型（每個都標了推薦／便宜／最強），也可以選「其他」手動填寫；
   - 填寫對應服務商的 API Key；選「自訂」時還要填介面地址。
3. 第一次使用建議勾上「演練模式」，先看看判斷準不準。
   需要的話勾上「整理輸出」，評分後自動分資料夾、重新命名（見下文「整理輸出」）。
4. 點「開始篩選」。細評開始前會彈窗顯示張數和預計用量，你確認後才會呼叫。
5. 完成後，報告直接顯示在介面裡，可以在報告裡：
   - 點 ★ 打 1–10 分（7–10 分的星是 AI 區間，手動也可以打），點 ✕ 標為淘汰；改動立即折算成星級，同步寫到 RAW 和 JPEG；
   - 勾選照片左上角的方框，再點「刪除所選」；或者點「刪除全部淘汰」，配對的檔案和 XMP 會一起移到廢紙簍。
   - 複核完點「按當前分數整理」，按你改過的分數整理到輸出資料夾。
   - 點照片卡片上的「編輯」，會直接切到「照片編輯」並開啟這一張。

介面只在本機執行（127.0.0.1），不對外開放。關掉終端視窗即可退出。
如果 macOS 提示“無法開啟，因為來自身份不明的開發者”：右鍵點啟動檔案 → 開啟 → 再點一次「開啟」。

### 兩種方式：社群快速篩片／常規篩片

進入照片篩選先選方式（兩張卡片，按 1／2 也行；之後點頁頭的方式名可以換）：

| | 社群快速篩片 | 常規篩片 |
|---|---|---|
| 做什麼 | 從全部照片裡直接挑出最好的 8／16／32 張 | 每張都評分，分成 精選／連拍瞬間／可用／淘汰 |
| 要選的 | 題材（人像／體育／活動／街拍／風光）、張數；用 AI 時可以寫想要什麼表現力、神情 | 輸出、整理、高階引數 |
| AI | 只送候選池（8 → 24 張，16 → 32，32 → 64），只要總分、符合度和一句評語 | 每組的代表和單張照片，五個分項＋總分＋評語 |
| 結果 | 複製到 `社媒快速筛片_题材_时间` 資料夾，按名次命名，附選片說明；不寫星級、原片不動 | 星級和色標、報告、整理輸出、AI 評語文件、審片台 |

快速篩片不會改動同一個資料夾裡常規篩片的結果，兩種方式可以先後都做。命令列：`python3 cull.py 照片文件夹 --quick 16 --genre sport --ai --brief "庆祝的瞬间"`。

**人像分野**：拍人像時（常規篩片的拍攝型別選「人像·活動」或「人像抓拍」，或者快速篩片的題材選「人像」），可以再選分野：cosplay、商業人像、戶外人像、活動人像，最多兩項（兩項時 AI 兩種標準兼顧，例如戶外 cosplay）。AI 按分野的標準打分、寫評語，並且知道這類拍攝裡做不到什麼（例如活動現場改不了燈光、漫展清不了場），不會拿這些扣分或提建議。隻影響 AI 細評；命令列 `--portrait-style cosplay,outdoor`。

**AI 評語**：評語先說最大的優點、再說最影響觀感的一個問題，都要指向畫面裡具體的位置；改進點先寫這張照片後期就能改的，再寫同樣條件下下次能做的，不提拍攝條件做不到的事；拍攝條件造成的問題（暗光噪點、現場混合光）說明原因、給後期辦法。


## AI 細評可選的模型

| 服務商 | 可選模型（第一個為預設） | API Key 從哪申請 | 環境變數 |
|---|---|---|---|
| Claude | `claude-sonnet-5-5`（推薦）、`claude-haiku-5-5`（便宜）、`claude-opus-5-5`（更強）、`claude-fable-5-1`（最強、最貴） | console.anthropic.com | `ANTHROPIC_API_KEY` |
| ChatGPT | `gpt-6.1-sol`（推薦）、`gpt-6-luna`（便宜）、`gpt-6-astra`（最強）、`gpt-5.5`（上一代） | platform.openai.com | `OPENAI_API_KEY` |
| Grok | `grok-4.7` | console.x.ai | `XAI_API_KEY` |
| Gemini | `gemini-3.8-flash`（推薦）、`gemini-3.6-flash`、`gemini-3.5-flash-lite`（便宜）、`gemini-4-argon`（最強） | aistudio.google.com | `GEMINI_API_KEY`（或 `GOOGLE_API_KEY`） |
| DeepSeek | `deepseek-flash` | platform.deepseek.com | `DEEPSEEK_API_KEY` |
| 自訂 | 自己填寫 | 各服務商 | `PHOTO_CULL_CUSTOM_API_KEY` |

- 列表核對於 2026 年 10 月，只列能看圖的模型。服務商出了新模型，選「其他（手動填寫）」直接填名字即可。
- **DeepSeek**：目前只有 `deepseek-flash` 支援圖片輸入（`deepseek-v4-pro` 只支援文字），所以只有這一個選項。
- **自訂（OpenAI 相容）**：填介面地址和模型名，就能接任何支援 Chat Completions 圖片輸入的服務，例如：
  - 通義千問 `https://dashscope.aliyuncs.com/compatible-mode/v1`（模型如 `qwen-vl-max`）
  - Kimi `https://api.moonshot.cn/v1`
  - 豆包（火山方舟）`https://ark.cn-beijing.volces.com/api/v3`
  - OpenRouter `https://openrouter.ai/api/v1`
  - 本機的 Ollama `http://127.0.0.1:11434/v1`、LM Studio `http://127.0.0.1:1234/v1`（不需要 Key）

  模型名和地址以各家文件為準。DeepSeek 和自訂介面直接走 HTTP，不需要額外安裝 SDK。
- API Key 都是按量付費，和網頁版訂閱（Claude Pro、ChatGPT Plus 等）無關。
- 已經評過的照片不會重複收費：快取按「服務商＋模型＋語言＋圖片」分別記錄。換了介面語言會重新細評一次，好讓評語換成新語言。
- 如果開頭連續 3 張呼叫失敗（Key 錯誤、模型名不對、餘額不足等），程式會自動停止細評，避免白白浪費。

## 命令列

```bash
# 只做本地筛选，不花钱
.venv/bin/python cull.py "/Volumes/SSD/2026-10-19 扫街"

# 先演练：只出报告，不写星级
.venv/bin/python cull.py "照片文件夹" --dry-run

# Claude 细评
export ANTHROPIC_API_KEY="…"
.venv/bin/python cull.py "照片文件夹" --ai

# ChatGPT 细评
export OPENAI_API_KEY="…"
.venv/bin/python cull.py "照片文件夹" --ai --provider openai

# Grok 细评
export XAI_API_KEY="…"
.venv/bin/python cull.py "照片文件夹" --ai --provider grok

# Gemini 细评
export GEMINI_API_KEY="…"
.venv/bin/python cull.py "照片文件夹" --ai --provider gemini

# DeepSeek 细评
export DEEPSEEK_API_KEY="…"
.venv/bin/python cull.py "照片文件夹" --ai --provider deepseek

# 任意 OpenAI 兼容接口（例：通义千问）
export PHOTO_CULL_CUSTOM_API_KEY="…"
.venv/bin/python cull.py "照片文件夹" --ai --provider custom --model qwen-vl-max \
    --base-url https://dashscope.aliyuncs.com/compatible-mode/v1

# 用英文输出报告、日志和 AI 评语（zh-CN／en／ja／ko）
.venv/bin/python cull.py "照片文件夹" --lang en

# 写完星级后，把淘汰的照片（含配对文件）移到废纸篓
.venv/bin/python cull.py "照片文件夹" --trash-rejects

# 评分后整理：保留（精选／连拍瞬间／可用）／淘汰 × JPEG／RAW，并按分数重命名（默认复制，加 --move 改为移动）
.venv/bin/python cull.py "照片文件夹" --organize "输出文件夹" --by-result --by-category --by-format --rename

# 调整精选线和精彩帧权重
.venv/bin/python cull.py "照片文件夹" --ai --pick-ai 7.5 --weights sharp=0.5,eyes=0.3
```

報告生成在 `照片文件夹/photo-cull-report/report.html`。同一目錄下還有 `results.csv`，可以用 Numbers 或 Excel 開啟。直接雙擊開啟的報告是隻讀的；要改分數或刪除，請在圖形介面裡操作。

## 評分規則（10 分制）

- **本地技術分**最高 **6 分**：對焦（本批照片裡比銳度）佔 60%、曝光佔 30%、人臉與睜眼佔 10%，換算到 1.0–6.0。「可能失焦」的最多 4 分；嚴重失焦、過曝、欠曝直接淘汰。
- **AI 細評**給出 1.0–10.0 的總分，**6 分以上只由 AI 給出**。細評過的照片以 AI 總分為準。
- 分數**內部精確到 0.1**，介面、報告、檔名只顯示整數部分。
- 寫進 XMP 時**折算成 1–5 星：分數 ÷ 2，向下取整**（7.9 分 → 3★，8.0 分 → 4★）。淘汰寫成「拒絕」（Rating −1）。

| 分數 | XMP 星級 | 色標 |
|---|---|---|
| 10 | 5★ | 綠色 |
| 8–9.9 | 4★ | 綠色 |
| 6–7.9 | 3★ | 黃色 |
| 4–5.9 | 2★ | 無 |
| 2–3.9 | 1★ | 紅色 |
| 0–1.9 | 不評星 | 無 |
| 淘汰 | 拒絕（−1） | 紅色 |

**分類**：每張保留的照片歸到下面三類之一（淘汰和讀取失敗另算）：

| 分類 | 怎麼來的 |
|---|---|
| 精選 | 單張照片，分數達到精選線：AI 細評過的 ≥ 7 分，只有本地分的 ≥ 5 分（兩條線都可以在「高階引數」裡改，命令列 `--pick-ai`／`--pick-local`）；**連拍組的代表**（送 AI 的那張）分數達到 AI 精選線時也進精選（「連拍代表達到精選線也算精選」，預設開，命令列 `--no-pick-bursts` 關掉） |
| 連拍瞬間 | 每組連拍（包括同場景重拍）按精彩幀權重**入圍 3–5 張**（4–19 幀 3 張、20–59 幀 4 張、60 幀以上 5 張；不超過 3 幀全部入圍），入圍的幀在時間上錯開，免得 120 張/秒的連拍挑出幾張幾乎一樣的。入圍裡精彩幀得分最高的一張是這組的**代表**，送 AI 細評（勾「連拍入圍的其餘幾張也細評」時其餘入圍的也送）；入圍但不是代表的最高 5.9 分 |
| 可用 | 其餘保留的照片，包括連拍裡沒入圍的幀（最高 4.9 分，即 2★） |

**精彩幀權重**（預設值，在「高階引數」裡可以改，命令列 `--weights`）：同一組連拍裡，按下面幾項的加權和挑一張。每項都在組內比較，權重不需要加起來等於 1。

| 專案 | 預設權重 | 看什麼 |
|---|---|---|
| 主體清晰 | 0.35 | 組內誰最銳 |
| 睜眼 | 0.25 | 檢測到的人臉裡有眼睛的比例 |
| 笑容 | 0.10 | 檢測到笑容的人臉比例 |
| 曝光 | 0.15 | 亮度適中、不溢位、不死黑 |
| 主體突出 | 0.15 | 最大的一張臉佔畫面多大（和組裡其他幀比） |

組裡每一幀都有 AI 分時（開了「連拍裡其餘的幀也細評」），按「AI 分 60%＋精彩幀得分 40%」重新挑。

**寫到哪裡**

| 檔案 | 星級（由分數折算）寫在 |
|---|---|
| RAW（DNG／ARW…） | 同名 `.xmp` 邊車檔案；配對的 RAW 和 JPEG 共用這一個 |
| JPEG | 檔案內嵌 XMP（可關閉：取消勾選「同步寫入 JPEG 內嵌 XMP」，或者命令列加 `--no-jpeg-embed`） |
| 單獨的 HEIC／HIF／PNG | 預設不寫；勾選「單獨的 JPEG／HEIC 也寫邊車 XMP」後寫邊車，Capture One 會讀 |

**Lightroom Classic**
- 新匯入的照片：匯入時會自動讀取星級。
- 已在相簿中的照片：
  1. 先選中照片，按 ⌘S（儲存後設資料到檔案），確保目錄裡的最新修改已經寫進檔案；
  2. 執行本工具；
  3. 最後選中照片，執行「後設資料 → 從檔案讀取後設資料」。
- RAW＋JPEG 如果是作為一張照片匯入的（Lightroom 預設設定），Lightroom 只顯示 RAW 的星級。想分別看到兩個檔案的星級，匯入前在「偏好設定 → 常規」裡勾選「將 RAW 檔案旁邊的 JPEG 檔案視為單獨的照片」。

**Capture One**
- 在「偏好設定 → 影像 → 後設資料」裡，把 XMP 邊車的「自動同步」設為「完全同步」或「僅讀取」。之後開啟資料夾，或對影像執行「從 XMP 重新載入後設資料」，就能看到星級和色標（選單名稱以你的 C1 版本為準）。

**刪除與目錄**
- 照片如果已經匯入 Lightroom 或 Capture One，在本工具裡刪除後，軟體裡會顯示“找不到檔案”，需要你在軟體裡一併移除。
- 剛刪錯了？開啟廢紙簍，把檔案拖回原來的資料夾即可。

## 整理輸出

評分完成後，可以把照片整理到一個輸出資料夾（不填路徑時是 `照片文件夹/整理输出`）。分法（2026-11-17 起）：

- **每次篩選一個上級資料夾**，名字是 `机型_筛选时间_分野`，例如 `ILCE-1M2_261117-2039_人像·cosplay＋户外人像`。分野：拍人像且選了人像分野時用分野，否則用拍攝型別（通用、體育·動作……）；一批裡有幾台相機時用張數最多的那台，後面註明一共幾台。
- 上級資料夾裡**只有「精選」和「可用」**。
- **連拍**：每組連拍在「可用」裡放 **2～3 張**，一組一個子資料夾（例如 `可用/连拍012_103045`：組號＋這組第一幀的拍攝時間）：代表進了精選時，可用裡放這組最好的另外 2 張；沒進時放代表＋最好的 2 張。這組**其餘的幀挪進原照片資料夾**裡新建的 `连拍_机型_时间_分野` 資料夾，每組一個子資料夾。**不管複製還是移動模式，這些多出來的幀都是挪過去，不留副本。**
- **淘汰的不整理**，留在原處。移動模式下，之後在報告裡改成淘汰的照片會搬回原照片資料夾、恢復原檔名；複製模式下刪掉它的副本。
- 複製／移動只管精選和可用：複製時這些照片的原檔案不動（APFS 上是克隆，不佔額外空間）；移動時搬到輸出資料夾。
- 命令列仍可以用 `--by-result`／`--by-category` 換回以前的 保留／淘汰 分法。

另外兩個選項照舊可以單獨開關：
- **再分 JPEG／RAW**：每個裡面再按格式分開；HEIC／PNG 等也放進 JPEG。
- **重新命名**：在原檔名前加上「分數_機型_」，分數是兩位整數，按檔名排序就是按分數排序，機型取自 EXIF，比如
  `08_ILCE-1M2_DSC01234.ARW`、`06_LEICA-M11-D_L1003467.DNG`、`X_X-T5_DSCF0001.RAF`。
  淘汰的是 `X_`；機型裡的空格和特殊符號換成 `-`。
  **只改輸出資料夾裡的檔案**，原檔名不變。
- **AI 細評過的照片用統一名稱**（勾了重新命名時）：`类别代码＋两位分数_编号_原文件名_R星级`，例如
  `P09_AI261104-2315-001_DSC01234_R4.ARW`。類別程式碼 `P` 精選、`M` 連拍瞬間、`U` 可用、`X` 淘汰（分數寫 `00`）；結尾 `_R0`～`_R5` 是 5 分制星級（和 XMP 一樣：分數 ÷ 2 向下取整），淘汰為 `_RX`，XMP 邊車檔案同名跟著改；
  編號 `AI<批次>-<序号>`，批次是這次篩選開始的時間（年月日-時分），序號按分數從高到低（同分按拍攝時間），配對的 RAW／JPEG 共用一個編號。
  統計時按 `_` 拆開即可，正則：`^([PMUX])(\d{2})_AI(\d{6}-\d{4})-(\d{3,})_(.+)_R([0-5X])(\.[^.]+)?$`。在報告或審片台裡改分後，編號不變，類別程式碼、分數和結尾星級跟著改。

### AI 評語文件與審片台

- 每次 AI 細評後，評語存成文件：報告資料夾裡的 `AI评语_<批次>.md`（一覽表＋逐張評語、分項分、可改進點）和同名 `.csv`（方便統計）；整理過的話，輸出資料夾裡也放一份，檔名和裡面的照片一一對應。改分、刪除、重新整理後自動重寫。
- **審片台**：篩選完成後，結果區上方切到「審片台」，只顯示 AI 細評過的照片，按編號排。左邊大圖，右邊是編號、統一名稱、分數、評語、分項分、可改進點和拍攝資訊；下面是膠片條，也可以切到網格。
  鍵盤：`←`／`→` 切換，`1`–`9`、`0`（＝10 分）打分，`X` 淘汰，`F` 全螢幕，`G` 單張／網格。打分和報告裡一樣，會同步寫 XMP、整理輸出和評語文件。

資料夾名跟隨整理時的介面語言（英文 `Kept`／`Picks`／`Burst moments`／`Usable`／`Rejected`，日文、韓文同理），並記在整理記錄裡；之後在報告裡改分數同步時沿用當時的名字。照片換了分類後，空出來的資料夾（比如某組連拍瞬間）會自動刪掉。

全部開啟時的結構：

```
整理输出/
├── 保留/
│   ├── 精选/
│   │   ├── JPEG/  08_ILCE-1M2_DSC01234.JPG
│   │   └── RAW/   08_ILCE-1M2_DSC01234.ARW  08_ILCE-1M2_DSC01234.xmp
│   ├── 连拍瞬间/
│   │   └── 连拍012_103045/
│   │       ├── JPEG/  07_ILCE-1M2_DSC01240.JPG
│   │       └── RAW/   07_ILCE-1M2_DSC01240.ARW
│   └── 可用/
│       ├── JPEG/
│       └── RAW/
└── 淘汰/
    ├── JPEG/
    └── RAW/
```

**複製還是移動**
- **複製**（預設）：原資料夾不動，輸出裡是副本，需要雙倍空間。之後在報告裡改分數，輸出裡的副本會自動換到對應的資料夾和名字；刪除照片時，副本也一起移到廢紙簍。再次整理不會重複複製。
- **移動**：照片從原資料夾搬到輸出資料夾。之後報告裡的改分數、刪除都會作用在新位置的檔案上。已經匯入 Lightroom／Capture One 的照片，移動後軟體會顯示“檔案丟失”，需要在軟體裡重新定位資料夾。

**其他細節**
- 配對的 RAW 和 JPEG 一起處理；RAW 的邊車 `.xmp` 跟著 RAW 走，重新命名時一起改名，所以 Lightroom／Capture One 匯入輸出資料夾也能看到星級。
- 重名時自動加 `-2`、`-3` 字尾，配對的兩個檔案用同一個字尾。
- 演練模式下只列出計劃，不會複製或移動任何檔案。
- 讀取失敗和已刪除的照片不參與整理。
- 輸出資料夾放在照片資料夾裡面也可以：勾了「包含子資料夾」時，下次篩選會自動跳過它。

## 說明與侷限

- **分析用哪個檔案**：有配對的 JPEG 時，用 JPEG 分析（全尺寸，顏色就是機內效果）；沒有 JPEG 時，用 RAW 裡嵌入的預覽。DNG、ARW 這類 TIFF 結構的 RAW，以及富士 RAF，由程式直接讀取內嵌預覽和 EXIF；CR3 等格式才需要 rawpy。
- **配對規則**：同一個資料夾裡，檔名相同、只有副檔名不同（不分大小寫），比如 `L1003467.DNG` 和 `L1003467.JPG`。放在不同資料夾裡的不會配對。
- **失焦判定**：用的是“再模糊”指標：把畫面再模糊一次，看邊緣變化有多大，所以和畫面細節多少無關；只取最銳利的區域，背景虛化的人像不會被誤判。預設閾值是用 Leica M11-D 的照片校準的，其他機身可能需要微調。
- **人臉、閉眼和笑容檢測**：用的是 OpenCV 的傳統檢測器，速度快但比較粗糙，只作提示和挑連拍瞬間的參考，不會因此淘汰照片。
- **AI 細評**：
  - 只把挑出的照片（單張，以及每組連拍挑出的那一張）縮成 1024 畫素的 JPEG 後上傳。
  - 結果快取在 `ai_cache.json`。
  - 不同模型的審美標準會有差異，評分只是參考，最終取捨請自己複核。

## 照片編輯（基礎版）

在右上角切換到照片編輯。也可以在篩選報告裡點照片卡片右上角的「編輯」，直接開啟那一張。左上角「篩選結果」按鈕會開啟照片篩選最近處理的資料夾。

**畫面調整**
- 基本：色溫、色調、曝光、對比度、高光、陰影、白色、黑色、清晰度、自然飽和度、飽和度、黑白。雙擊滑塊名稱可以復位。
- 曲線：RGB 總曲線和紅／綠／藍分通道曲線。點選加點、拖動調整、雙擊刪除。
- **預覽**：按圖片在螢幕上實際佔的畫素（含 Retina 高分螢幕）取清晰度，視窗變大會自動重渲染；點一下預覽圖放大到螢幕畫素 1:1（可滾動檢視細節），再點或按 Esc 回到適應視窗。左右兩欄可以用標題欄的 ◧ ◨ 按鈕或鍵盤 `[` `]` 收起，讓預覽佔滿視窗，設定會被記住。左側檔案列表有「小圖／大圖」兩檔縮圖。
- 監看：RGB 直方圖（標出高光溢位和暗部死黑的比例），以及亮度波形圖／RGB 分量波形圖。
- 「按住對比原圖」可以看調整前的樣子。
- **自動調整**：工具欄的下拉選單裡選測光方案，再點「自動」。之後仍可手動微調。都是按各家相機的測光思路和成片觀感做的經驗設定，**不是機內演算法的復刻**。測光直接在編輯器的真實渲染結果上做，RAW 的起始提亮、JPEG 的直出亮度、當前色溫色調和已選的鏡頭暗角都算在裡面。

  每個方案先定**曝光**，再定**整體影調**（設定「對比度／黑色／白色」三個滑塊）：

  | 方案 | 測光 | 影調 |
  |---|---|---|
  | 全域性評價 | 整幅畫面分 6×4 區，去掉最亮、最暗的 15% 分割槽再平均，目標 18% 灰 | 中性：黑位、白位適中，對比不加不減 |
  | 徠卡經典中央重點（預設） | M 機身式中央重點，目標比 18% 灰低約 1/4 檔；暗景只補一部分 | 深沉：黑位壓得最深、基礎對比 +12，從不降低對比 |
  | 徠卡全域性測光 +0.3EV | 徠卡多區測光，再加 +0.3 檔補償 | 同徠卡，略通透（基礎對比 +8） |
  | 富士中央重點 | 中央區域比徠卡更寬，目標 18% 灰；高光保護更嚴 | 柔和：黑位留一點、基礎對比 −5、過渡平緩 |

  影調的規則：平淡發灰的畫面多加一點對比，已經很硬的少加或略減；對比只看去掉純黑純白之後“有內容”的部分，所以大面積黑底的低調照片不會被誤判。黑色只往深壓（純黑不會被抬成灰黑），白色只往亮推（到頂的純白不會被壓成灰白）；低調照片不硬拉白，高調照片不硬壓黑。所有方案在高光溢位過多時都會收一點曝光。上次選的方案會被記住。

  HDR 動態測光暫時不提供，之後會和 HDR 顯示模式一起推出。
- **鏡頭暗角**：在「基本調整」下方選鏡頭和強度，模擬經典徠卡 M 鏡頭未經機身校正的光學暗角（正圓、漸變、四角最暗）：

  | 型號 | 鏡頭 | 弱（≈f/5.6） | 中（≈f/2.8） | 強（光圈全開） |
  |---|---|---|---|---|
  | 11874 | Summilux-M 35mm f/1.4 ASPH.（1994 版，非 FLE） | −0.6 檔 | −1.2 檔 | −2.2 檔（f/1.4） |
  | 11699 | APO-Summicron-M 35mm f/2 ASPH. | −0.8 檔 | −1.3 檔 | −1.9 檔（f/2） |
  | 11141 | APO-Summicron-M 50mm f/2 ASPH. | −0.5 檔 | −0.9 檔 | −1.4 檔（f/2） |
  | 11672 | Summicron-M 28mm f/2 ASPH.（2016 第二代） | −1.0 檔 | −1.6 檔 | −2.3 檔（f/2） |

  數值是四角比中心暗多少檔。徠卡的資料表只以曲線圖給出暗角，沒有公開數值，這裡是按各鏡頭的設計特點（焦距、最大光圈、鏡身大小）做的近似；大光圈、廣角的暗角從更靠近中心的地方開始。M 機身拍攝時通常會按鏡頭編碼自動校正暗角，這裡模擬的是校正前的光學原貌。匯出時同樣生效；「基本調整」的「重置」會一併清除。
- 調整會自動儲存到 `照片文件夹/photo-cull-report/edits/`，原檔案不會被修改。「複製設定／貼上設定」可以把一張的調整用到另一張。

**支援的格式**
- RAW 由 LibRaw（rawpy）解碼：徠卡 DNG（M11、Q3、SL 等）、松下 DNG／RW2、索尼全部 ARW（未壓縮、壓縮、無失真壓縮）、富士 RAF（X-Trans 和拜耳機型，包括壓縮 RAF）。DNG 裡的 BaselineExposure 會自動套用。
- 也能編輯 JPG、HEIC、TIFF、PNG。
- 如果 RAW 解碼失敗（比如非常新的機型 LibRaw 還不支援），會自動改用 RAW 裡嵌入的預覽圖編輯，並在介面上提示；這時畫質和寬容度有限。

**風格（LUT）**
- **內建 LUT**：工具資料夾的 `luts/` 裡自帶 39 個 LUT：Fujifilm GFX 膠片模擬 20 個（命名「機型 + 膠片模擬名 (sRGB)」，如 `GFX50S PROVIA (sRGB)`）、Leica Look 19 個（命名「Leica Look + 濾鏡名 (sRGB)」，如 `Leica Look CHR (sRGB)`）。**工作空間均為 sRGB**，用在已轉成 sRGB 的畫面上，不要套在 Log 或線性素材上。LUT 收集自公開渠道，品牌名只用於說明風格。預設就用它們，拷到別的電腦（包括 Windows）也能直接用；編輯記錄裡儲存的是「內建 LUT 的名字」而不是這台電腦上的路徑。
- **新增自己的 LUT**：在「風格（LUT）」裡點「新增 LUT…」選一個或多個 `.cube` 檔案，會先檢查格式再存到 `~/.photo-cull/luts`（升級工具不會丟），列表裡顯示在「我的 LUT」分組；滑鼠移到條目上點 × 可移除。
- 搜尋後點一下 LUT 就能套用，強度可以調。想用別的素材庫，點「選擇…」換資料夾；點「內建」換回來。選擇外部素材庫時，列出裡面全部的 LUT 和預設。
- **輸入空間**：統一按 sRGB 處理，對應索尼「ST 標準」／徠卡「STD」的機內畫面。
  - JPEG：用 ST／STD 模式拍的 JPEG，和 LUT 的設計輸入完全對應。
  - RAW：以編輯器的標準渲染作為這一畫面的近似，再套 LUT。
- S-Log3 等相機 Log 的轉換暫未啟用（程式碼裡保留，`photo_cull/edit/logspace.py` 中的 `ENABLE_LOG`）。
- 編輯器也能解碼 XMP 預設裡的 Adobe 色彩表（RGBTable／LookTable）；當前素材庫範圍內沒有 XMP，這部分暫時用不到。

**匯出**
- JPEG（可選品質，內嵌 sRGB 色彩配置和拍攝引數）或 16 位 TIFF；可以選原尺寸，或把長邊縮到 6000／4000／2048。
- 匯出到照片所在資料夾的 `photo-cull-export` 子資料夾，不會覆蓋原圖。
- 匯出時按全解析度解碼、分條渲染，6000 萬畫素的照片也不會佔滿記憶體。預覽和匯出用的是同一條處理管線，每條內部再多執行緒處理。

**說明**
- 高光、陰影是全域性曲線調整，不像 Lightroom 那樣做區域性色調對映，大幅推動時效果會不同。
- 預覽在後台渲染：拖動滑塊時先出低清圖，鬆手後再出高畫質圖。渲染會用滿電腦的多個核心；大 JPEG 預覽按需縮小解碼，縮圖優先用檔案裡內嵌的小預覽圖（索尼 JPEG、ARW 都帶），資料夾開啟得更快。

## 開發記錄

原始碼採用前後端分離：Python 包 `photo_cull/` 只負責處理照片和提供介面，介面是 `web/` 裡的 HTML／CSS／JS，文字都在 `locales/` 語言包裡。改介面不用碰 Python，改文字不用碰程式碼。

```
photo_cull/
  imaging/   读图与 EXIF（RAW 内嵌预览直读、HEIF、富士 RAF），筛选和编辑共用
  cull/      照片筛选：analysis 分析 → grouping 分组 → scoring 评分 → ai/ 细评 → xmp → organize 整理 → report 报告；pipeline 串起各阶段，cli 是命令行
  edit/      照片编辑：color 色彩、lut3d／refs／styles LUT、presets 预设、render 渲染、auto 自动调整、session 编辑会话、export 导出
  server/    本地网页服务：settings 设置、jobs 任务、apps 两个程序的登记、pages 页面、actions 报告里的操作、handler 接口、runtime 一体窗口
  i18n.py · paths.py · version.py · activation.py（激活码）
cull.py · gui.py · desktop.py      入口（命令行、本地网页、Mac 应用）
tests/                              测试：python3 tests/run.py
```
