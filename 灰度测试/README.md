| 文件 | 给谁看 | 写什么 |
|---|---|---|
| [灰度测试计划.md](灰度测试计划.md) | 你 | 目标、范围、时间、测什么、什么时候算结束 |
| [测试者须知.md](测试者须知.md) | **测试的人**（随应用一起发） | 怎么安装、激活、测什么、怎么反馈 |
| [激活码发放记录.md](激活码发放记录.md) | 你 | 把激活码告诉了谁（试用名单；**不写激活码本身**） |
| [版本记录.md](版本记录.md) | 你 | 每次打包发出去的是哪一版、改了什么 |

## 一条线看全过程

```
开发版 photo-cull-main（改代码、跑测试）
   │
   └─ tools/导出发布版.command：问激活码（只在你脑子里，不写进任何文件）
        → 临时文件夹里精简导出、写进激活码的哈希、打包
        ▼
      photo-cull-main-release（只放成品）：PhotoCull-…-macOS.zip ＋ 安装与激活说明.md ＋ 发布记录.md
        │  （自动复制一份到 Grey-test/Pre-A/）
        │  zip ＋ 安装与激活说明 ＋ 测试者须知 ──▶ 测试的人；激活码当面／单独告诉
        │                                   ◀── 反馈、运行记录
        ▼
      反馈记录.md → 回开发版修 → 再做一次发布包 → 版本记录.md 记一笔
```

## 规矩

- 只有一个共用激活码：告诉谁谁就能用，不绑电脑。要收回，就换一个码重新做发布包（旧包里的码随之作废，已经激活的也要重新输入新码）。
- **代码只在开发版改。** Grey-test 里只放成品包和文档，不放源码。
