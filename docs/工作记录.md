## A2. 11-01 之后做了什么

### A11-10：内存和性能（没提交）
- **内存上限**：同时解码的照片按内存预算排队，单张约每像素 8 字节（24MP 约 185 MB）。默认预算是物理内存的 20%（16 GB 机器 3.2 GB），可改。
- **AI 预览图在内存里存 JPEG 字节**：每张约 7 MB → 0.3 MB。
- **整理时秒拷**：Mac 同一个 APFS 卷上用 `clonefile`，跨卷自动退回普通复制。
- 详见项目文档《照片工具-内存上限与性能-1110》。

### A11-14：快速筛片、预设、筛选标准（没提交）
- **两种筛片方式**：社媒快速筛片／常规筛片。
- **社媒快速筛片**（`cull/quick.py`）：按题材从全部照片里挑出最好的 8／16／32 张。本地初选（每组连拍留一张、覆盖整场拍摄）→ AI 只评候选（8→24、16→32、32→64）→ 复制到 `社媒快速筛片_题材_时间` 文件夹，按名次命名。可以写「想要什么样的照片」让 AI 重点看。只看 JPEG 或 RAW 一种，复制时同名的另一种一起带上，分放 `JPEG`／`RAW` 两个子文件夹。不写星级、不动原片、不改常规筛片的结果。
- **关闭前询问**：快速筛片复制过的照片，关窗口前问要不要把原位置的文件移到废纸篓；结果页也有按钮。只动副本确实还在的文件。
- **常规筛片：目标精选数量**（`--pick-target`）：按分数从高到低正好取 N 张。
- **筛选预设**（`server/presets.py`）：严格度（宽松／标准／严格）＋ 拍摄类型（通用／人像·活动／人像抓拍／体育·动作／风光·静物）。高级参数收进**开发者模式**，要先确认风险说明。
- **筛选标准**（`cull/criteria.py`）：常规筛片用 AI 时可以写标准，并选「AI 更看重」的分项；总分 = AI 总分 + 0.5 ×（选中分项平均 − 五项平均），最多 ±1。
- **界面过渡**：动效的时长和曲线统一放在 `tokens.css`；启动界面淡出、分段按钮滑块、进度流光、大图从缩略图位置放大等。
- 详见项目文档《照片工具-快速筛片与界面过渡-1114》。

- 用户自己调过的高光 0.05、暗部 0.5 要不要并进某一档严格度（连拍间隔 5／同场景 30／相似度 0.7 已经做成「人像抓拍」）。
- 并行数、内存上限要不要也放进流程卡片。
- 流程卡片里要不要能进开发者模式（现在只在高级模式）。
- 桌面文件整理：11-09 提过，用户中途停了，没有继续。

### A3.4 提过但没做
- 性能建议 1（半尺寸解码，本地分析约快一倍，但分数会略变）、建议 4（结果常驻内存、延迟写盘）：11-10 用户只批准了建议 2、3。
- 流程卡片模式下刷新页面（比如切换语言）时如果正在运行或已有结果，会回到高级模式的界面显示，没有回到卡片。

- 画布里的原型没有同步第一张卡片的大卡片样式。

### A3.5 已知的问题和风险
- `test_server` 偶尔失败的原因 11-17 查明并修了（点开始后极短时间内查状态得到「没在运行」）。
- 11-14 写回过一版有脚本错误的界面（「按哪种文件筛」，页面只显示「链接已失效」），同一天已修复。教训：改了界面要实拍再写回。

# 第二部分：结构与实现要点（写到 1.8-beta、11-01）

## B1. 项目概述

本地运行的 Python 照片工具，由两个程序组成，放在同一个窗口里，共用一个本地网页服务（`photo_cull/server`）：

| 程序 | 启动 | 作用 |
|---|---|---|
| 照片筛选 | `gui.py --start cull`（`启动筛选`） | 10 分制打分（本地 ≤ 6、AI 给 6 以上）、连拍挑精彩帧、XMP 星级/色标、RAW+JPEG 配对、HTML 报告、按 精选／连拍瞬间／可用／淘汰 整理与重命名 |
| 照片编辑 | `gui.py --start edit`（`启动编辑`） | 基础修图：滑块、曲线、直方图/波形、LUT、自动调整、镜头暗角，导出 JPEG / 16 位 TIFF |

只依赖本机：图片不上传（AI 细评除外，需用户自己填 API Key）。界面、报告和 AI 评语支持简体中文、English、日本語、한국어。

## B3. 功能与实现要点

### B3.1 照片筛选（`photo_cull/cull`）
- **配对**：同文件夹、同名（不区分大小写）的 RAW 和 JPEG 视为一组，共用一个 XMP 边车文件。
- **写入**：星级与色标写 XMP；JPEG 可另写内嵌 XMP，写完逐字节核对图像数据未变。
- **删除**：走系统废纸篓（send2trash），失败时移到 `_待删除` 文件夹，不直接删。
- **整理输出**：`保留（精选／连拍瞬间／可用）／淘汰` × `JPEG/RAW`，连拍瞬间每组一个文件夹（`连拍012_103045`），可选复制或移动；清单文件 `.photo-cull-organize.json` 让重复运行不产生重复文件；重名加 `-2`（一组文件共用同一后缀）；RAW 的 XMP 跟着 RAW 走。在报告里改分数或删除后，输出文件夹同步更新，空出来的文件夹自动删除。
- **重命名**：`分数_机型_原名`（两位数，如 `08_ILCE-1M2_DSC01234.ARW`，淘汰为 `X_`），机型来自 EXIF 并去掉非法字符，只改输出文件夹里的文件。
- **富士 RAF**：识别文件头 `FUJIFILMCCD-RAW`，按偏移 84/88 读取内嵌 JPEG。
- **命令行**：`--organize [DIR] --by-result --by-category --by-format --rename --move`、`--pick-ai`／`--pick-local`、`--weights`、`--lang zh-CN|en|ja|ko`、`--provider … --base-url …`。
- **保存的数据不含语言**：问题标记存代码（`blur`、`soft`、`under`、`over`、`clip_high:0.052`、`clip_low:…`、`eyes`、`xmp_fail:原因`），题材存 `portrait/street/landscape/architecture/event/other`，分类存 `pick/moment/usable/reject/error`，显示时再翻译；载入 1.5 及以前的结果时把中文句子转换成代码（`FLAG_LEGACY`、`GENRE_LEGACY`）。
- **整理文件夹名**：保留／淘汰／精选／连拍瞬间／可用／连拍组 的名字按整理时的语言取，记在整理记录的 `dirs` 里，之后改分数同步时沿用；1.6–1.7 的记录只有 `keep_dir`／`reject_dir`，更早的按中文名处理。

### B3.1.1 评分（1.8-beta 起 10 分制）
- 分数 `score` 精确到 0.1，界面、报告、文件名只显示整数部分（`model.shown`）。
- 本地分 `local_score`：`1 + 5 × (0.6 锐度百分位 + 0.3 曝光质量 + 0.1 人脸)`，即 1.0–6.0；「可能失焦」封顶 4.0；严重失焦／欠曝／过曝 → 淘汰。
- AI 细评过的照片以 AI 总分（1.0–10.0）为准，所以 6 分以上只能来自 AI。连拍里没被选中的帧封顶 4.9。
- XMP 星级 = `floor(score / 2)`（`model.xmp_stars`），淘汰 −1；色标跟星级走（4–5★ 绿、3★ 黄、1★／拒绝 红）。
- 分类：单张且达到精选线（AI ≥ 7、本地 ≥ 5）→ 精选；连拍组里挑出的一张 → 连拍瞬间；其余保留 → 可用。
- 连拍入围（11-06）：每组按精彩帧得分入围 3–5 张（`scoring.shortlist_size`／`pick_shortlist`，时间上错开），入围的都是连拍瞬间、放同一个组文件夹（`Photo.group_tag`）；代表（`group_best`）从入围里挑，默认只有代表送 AI。起因：A9 III 120 张/秒，957 组里 849 张落在 50 组（最大 141 帧），每组只留 1 张太少。
- 精彩帧权重 `HIGHLIGHT_WEIGHTS`：主体清晰 0.35（组内锐度百分位）、睁眼 0.25、笑容 0.10、曝光 0.15、主体突出 0.15（最大人脸面积 ÷ 组内最大值）；组内每帧都有 AI 分时 AI 占 60%。
- 手动打分（报告里 1–10、✕ 淘汰）记 `manual`，重跑同一文件夹时沿用。

### B3.1.2 AI 细评
- `PROVIDERS`：每家的显示名、环境变量、默认模型、可选模型和说明（`notes` → 语言包 `cull.model_note.*`）、调用方式 `api`：
  - `messages`：Claude（anthropic SDK）；`responses`：ChatGPT、Grok（openai SDK 的 Responses API）；`gemini`：Gemini REST；
  - `chat`：OpenAI 兼容 Chat Completions，用标准库直接发 HTTP（`_chat_caller`），DeepSeek 和自定义接口走这里，不需要 SDK。
- 模型列表（2026-10 核对，只列能看图的）：Claude sonnet-5-5／haiku-5-5／opus-5-5／fable-5-1；ChatGPT gpt-6.1-sol（默认）／gpt-6-luna／gpt-6-astra／gpt-5.5；Grok grok-4.7；Gemini 3.8-flash／3.6-flash／3.5-flash-lite／4-argon；DeepSeek deepseek-flash（DeepSeek 唯一支持图片输入的模型，v4-pro 只支持文字）。
- 自定义接口：用户填 `base_url` 和模型名（`--provider custom --base-url …`），Key 用界面填写或 `PHOTO_CULL_CUSTOM_API_KEY`；本地服务没有 Key 时自动用占位值。
- 提示词 `AI_PROMPTS` 按语言各一份（中、英、日、韩），要求 1.0–10.0 一位小数的总分，评语和改进点用该语言写；缓存键为 `服务商:模型:语言:图片哈希`，1.5 及以前的中文缓存在中文界面下仍可命中。

### B3.1.3 AI 统一编号、评语文档、审片台（11-05）
- `cull/ainame.py`：`assign_ids` 在定分之后给 AI 细评过的照片编号 `AI<YYMMDD-HHMM>-<序号>`（分数从高到低、同分按时间、淘汰最后），存 `Photo.ai_id`；`organize.org_name` 对有编号的照片用 `ai_name`：`P09_AI…-001_原名`（P／M／U／X）；`strip_prefix` 去掉两种前缀。
- `write_doc`：`AI评语_<批次>.md`／`.csv` 写进报告文件夹（整理过的话输出文件夹也放一份），记在 `meta.ai_doc`（含写文档时的语言）；`server/actions` 在改分、删除、重新整理后重写。
- 审片台：`server/review.py`（`review_data`、`review_image`：只给有编号的照片出大图，缓存在 `review/`）、页面 `web/review/`；筛选页结果区 `#paneSeg` 在报告和审片台之间切换，改分后用 `postMessage` 更新统计。
- 测试：`tests/test_review.py`（编号顺序、命名、文档、审片台数据和大图、改分后名字和文档同步）。

### B3.2 照片编辑（`photo_cull/edit`、`web/edit/`）
- **渲染管线**：线性 ProPhoto → 白平衡/曝光 → 镜头暗角 → LookTable → 基础色调（仅 RAW）→ sRGB 编码 → 曲线/RGBTable → 清晰度 → 饱和度、自然饱和度、用户曲线、LUT、黑白。预览和导出走同一条管线。
- **自动调整**（`METER_STYLES`）：全局评价、徕卡经典中央重点（默认）、徕卡全局 +0.3EV、富士中央重点。曝光在真实渲染结果上二分求解（中央重点用高斯加权，全局用 6×4 分区去极值），阻尼防止过度调整，高光过曝保护；之后按方案设定对比度、黑场、白场。HDR 动态方案在 `HDR_STYLES` 里，由 `ENABLE_HDR=False` 隐藏。
- **镜头暗角**（`LENSES`）：11874（35/1.4）、11699（35/2 APO）、11141（50/2 APO）、11672（28/2）× 弱/中/强（约等于 f/5.6、f/2.8、全开）。模型为线性空间里的 `ev · r^p`；数值是根据公开曲线估计的近似值。
- **LUT**：
  - 内置 39 个，见第 4 节。引用写成 `builtin:相对路径`。
  - 用户添加的 LUT 存在 `~/.photo-cull/luts`，引用写成 `user:文件名`，在列表里归入「我的 LUT」。添加时检查格式（必须有 LUT_3D_SIZE 2–129 或 LUT_1D_SIZE，数据完整，单个文件不超过 64 MB），重名自动加 `(2)`；只能移除自己添加的文件。接口：`/api/edit/lut_add`、`/api/edit/lut_remove`。
  - 也可以把素材库切到任意外部文件夹（列出其中全部 `.cube` 和 `.xmp` 预设）。
- **界面**：缩略图小图/大图切换，左右面板可折叠（`[` `]`），点击放大，预览分辨率按显示尺寸在 1400/1800/2400/2880 中选择。

### B3.3 前后端分离与多语言
- 网页服务（`server/pages.py`）收到 `/` 时读取 `web/<app>/index.html`，替换 `__VER__`、`__LANG__`、`__I18N__`（当前语言的语言包 JSON）后返回；`/static/*` 提供 `web/` 下的 CSS/JS（只允许这些扩展名，不需要令牌）。每次请求都读文件，改界面刷新即可。
- 语言包：`i18n.strings(lang)` = 简体中文 ← 英文 ← 所选语言 逐层覆盖，缺的条目自动回退；网页端缺键会在控制台警告。`common.file_manager`／`common.trash` 由网页服务按系统（访达／资源管理器、废纸篓／回收站）补上。
- 语言选择：右上角下拉 → `POST /api/lang` 写 `~/.photo-cull/lang.json`（两个程序共用）→ 刷新；筛选程序已有结果时按新语言重新生成报告。第一次打开（没有保存过）按浏览器语言自动选择。
- 后端显示用的名字（测光方案、镜头、暗角档位、LUT 分组、不支持的预设项）都在取用时翻译（`meter_list()`、`lens_list()`、`vig_levels()`、`builtin_group_label()`、`unsup_text()`）；LUT 文件夹名本身不变，免得编辑记录里的引用失效。
- 报告页：`write_report()` 把 `tokens.css`、`report.css`、`i18n.js`、`report.js`、报告用到的语言分组和数据内联进一个 `report.html`，可以单独拷走打开。CSV 表头也按语言写。
- 检查工具：`tools/check_i18n.py` 检查四种语言键是否一致、占位符是否一致、代码里直接引用的键是否都存在。

### B3.4 两个程序的协作（`photo_cull/server`）
- **一体模式（默认）**：`gui.py --app all --start cull|edit`（启动文件、Mac 应用都用它）在同一进程里起两个本地服务（各一个端口，`server.app` 区分），`/shell` 页面用两个 iframe 装两个界面；页头切换按钮、⌘1／⌘2、报告里的「编辑」通过 `postMessage` 通知外层切换（`web/common/shell.js`）。当前界面和编辑中的照片记在地址参数里，整页刷新（切换语言）后回到原处；筛选页刷新后从 `/api/status` 恢复进度或结果。再次启动时发现已有一体进程，直接打开它的窗口。
- **单独模式**：`--app cull|edit`，需要另一个程序时自动在后台启动（`start_peer`，打包后的应用不需要）；设置 `PHOTO_CULL_NO_AUTOSTART=1` 可关闭（测试用）。
- **Mac 应用**：`tools/build_mac_app.py` 在单独的 `.venv-build` 里装 PyInstaller、pywebview，按 `packaging/photo-cull.spec` 打包成 `dist/mac/照片工具.app`（web、locales、luts 作为资源打进去，`photo_cull` 的全部子模块用 `collect_submodules` 收进去），再运行 `PhotoCull --selftest` 自检，最后用 `ditto` 生成分发用 zip。窗口用 pywebview（系统 WebKit），不能开新标签页的地方（「在浏览器中打开报告」）改由后端调用默认浏览器。应用日志在 `~/.photo-cull/logs/app.log`，网页存储在 `~/.photo-cull/webview`。
- 每个程序启动后写注册文件 `~/.photo-cull/apps/<app>.json`（端口、令牌、进程号，权限 600）。
- `/open/<app>` 跳转到另一个程序；对方没开时显示启动提示页。
- 跨程序接口互相隔离（筛选端访问编辑接口返回 404，反之亦然）。

### B3.5 性能
- JPEG/MPO 按需缩小解码（PIL draft）；缩略图优先用文件内嵌的小预览（索尼 JPEG、ARW 都带）。
- 渲染缓存、按预览级别缓存缩放图；平面（R/G/B 分开）内存布局；四面体插值 3D LUT 重写（结果与旧实现逐位一致）；逐像素阶段多线程分块，清晰度等整图阶段单独处理。
- 实测（2 核容器，2880 档）：LUT 渲染 1737 → 649 ms，拖动预览约 36 ms。

### B3.6 部署与打包
- `tools/setup_env.py`：找 Python ≥ 3.9 → 建独立环境（macOS/Linux `.venv`，Windows `.venv-win`）→ PyPI 4 秒连不上就换清华镜像 → 安装依赖 → 逐个导入检查组件、核对 LUT 数量和设置文件夹可写。用 `requirements.txt` 的哈希判断环境是否需要更新。参数：`--check --recreate --mirror tuna|aliyun|ustc|pypi --wheels DIR --download DIR --target win|mac-arm|mac-intel|linux`。
- （11-17 去掉）Windows 启动脚本、`.venv-win`、`tools/make_release.py`（源码 zip）。照片工具私有后只发布打包好的应用。

### B3.7 第三模块：胶片冲印（photo-cull-film）
- 和照片工具的连接只走本机 HTTP：胶片冲印启动时写 `~/.photo-cull/apps/film.json`（运行中）和 `film-install.json`（安装位置）；照片工具 `server/film.py` 据此判断是否安装、是否在运行，需要时用它自己的 Python 启动（独立进程，去掉 PyInstaller 的环境变量）。
- 一体窗口：`/shell` 多一个 `f-film` iframe，第一次切过去时 POST `/api/film` 拿地址；照片编辑的「胶片冲印」按钮发 `{pc:"open-film", path}`；页面语言包里带 `film` 标志，装了才显示第三个页签。
- 测试：`tests/test_film_link.py`（用一个假的胶片冲印进程）；胶片冲印自己的测试用 spektrafilm 替身。

## B4. 内置 LUT

| 分组 | 数量 | 命名规则 | 示例 |
|---|---|---|---|
| `Fujifilm GFX 胶片模拟 (sRGB)` | 20 | 机型 + 胶片模拟名 (sRGB) | `GFX50S PROVIA (sRGB)`、`GFX100 II REALA ACE (sRGB)` |
| `Leica Look (sRGB)` | 19 | Leica Look + 滤镜名 (sRGB) | `Leica Look CHR (sRGB)`、`Leica Look BW HC (sRGB)` |

- 工作空间全部为 sRGB：文件名、`TITLE` 和文件头注释都有标注，编辑器按 sRGB 套用。
- LUT 收集自公开渠道；文件头里原有的宣传注释已去掉，调色数据未改动（与原文件逐个核对一致）。
- 改名过程：原始文件名 → 一度改为中性名（C01–C23 / M01–M16）→ 现名。三代名字到现名的对照在 `lut-aliases.json`（工具文件夹或 `~/.photo-cull` 里，已列入 `.gitignore`，不发布），旧编辑记录据此自动对应。

## B5. 主要问题与修复

| 问题 | 原因 / 修复 |
|---|---|
| 缩略图卡片被压扁 | 自动高度网格里 `overflow:hidden` → 改用内边距包裹层 + `grid-auto-rows:max-content` |
| 折叠左面板后布局错列 | 给各区域固定 `grid-column` |
| 分块导出与整图渲染有细微差别 | 暗角坐标改 float64；清晰度分块边距改 4σ+2 |
| 奇数尺寸图片尺寸差 1 像素 | 保存原始尺寸，按旋转方向还原 |
| 索尼 JPEG（MPO）没走快速解码 | 补充 MPO 格式和预览帧逻辑 |
| 最终着色阶段慢 | 改为索引查表 + 平面缓冲 |
| 清晰度+饱和度并行后反而变慢 | 拆分逐像素阶段（并行）和整图阶段 |
| 设备同步偶尔写入旧内容 | 每次部署用新的暂存目录，并核对 md5 |
| 切换语言后筛选页仍是中文 | 图形界面在同一进程里调用 `cull.main --lang`，覆盖值没有还原 → 不再传 `--lang`，且 `cull.main` 结束时恢复原值 |
| 选中文时显示成英文 | 语言回退顺序写反（英文覆盖了中文）→ 改为 简体中文 ← 英文 ← 所选语言 |
| 日文界面「入力色空間」竖排 | 标签写死 62px 宽 → 改为不换行、自适应宽度 |
| 约 2000 张、并行 10 时程序闪退（SIGSEGV） | 多个线程共用一个 OpenCV `CascadeClassifier` 同时检测 → 每个线程各自加载一份（1.7.1） |
| 项目文件夹移动后打包失败 | `.venv-build` 里的 python 还指着旧路径 → 失效自动重建，并改用系统 Python 建环境（1.7.1） |
| 1.7.1 的 80G 实测：保留里只有一个文件夹，精选和连拍混在一起 | 1.8-beta 改为 10 分制＋精选／连拍瞬间／可用 分类，连拍按精彩帧权重挑一张 |
